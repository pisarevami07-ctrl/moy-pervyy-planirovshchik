# Техническое задание: личный планировщик «Мой день»

Версия: 1.3. Дата: 9 октября 2026 года. Язык интерфейса: русский.

Версия 1.2 учитывает последующие пожелания пользователя: персиковый фон, чистый фисташковый блок, прогресс сегодняшних задач и часы бытовых блоков по дням недели.

Версия 1.3 заменяет цвет «Не сегодня» на мятный по образцу пользователя и добавляет постоянную отмену последнего выполнения.

## 1. Назначение и приоритет требований

Создать настольную веб-страницу для реалистичного планирования текущего дня. Пользователь задаёт границы дня, добавляет задачи и обязательные бытовые блоки, меняет приоритеты, видит рассчитанное расписание с перерывами и предупреждениями, откладывает дела и находит выполненные задачи в архиве.

Это окончательная спецификация первой версии. При расхождениях с `concept.md` и изображениями-макетами действуют требования этого ТЗ. Все решения ниже обязательны для реализации; дополнительных решений от пользователя для написания кода не требуется.

Ключевые изменения относительно первоначальной концепции: планировать можно только сегодня; задачи разрешено дробить и использовать менее приоритетные дела для заполнения коротких промежутков; главные и мелкие задачи образуют два раздела общего списка; после выполнения оставшееся расписание пересчитывается от текущего времени; завтрак и обед имеют длительность по умолчанию 30 минут с возможностью изменения.

## 2. Формат продукта и ограничения

1. Результат разработки — ровно три файла приложения в одной папке: `index.html`, `style.css`, `script.js`.
2. Использовать обычные HTML, CSS и JavaScript, без сборщика, установки пакетов, фреймворков, CDN, внешних шрифтов и сетевых запросов.
3. HTML подключает CSS относительным путём, JS — обычным скриптом с `defer`. Не использовать ES-модули и загрузку локальных ресурсов через `fetch`.
4. Запуск — открытием `index.html` в браузере. Сервер, база данных и облачный аккаунт не требуются.
5. Данные хранятся в `localStorage`. Экспорт и импорт резервных копий выполняются локальными JSON-файлами.
6. Целевые браузеры — актуальные настольные Microsoft Edge и Google Chrome на Windows. Основная проверка интерфейса — при ширине окна от 1024 px. При меньшей ширине блоки складываются в одну колонку, без горизонтального обрезания элементов.
7. Основной способ управления — мышь; все действия также доступны с клавиатуры. Поддержать касание и стилус на настольных Windows-устройствах через Pointer Events. Отдельный мобильный интерфейс не требуется.
8. Не создавать регистрацию, роли администратора, совместную работу, заметки, подзадачи, повторяющиеся задачи, синхронизацию устройств, редактор мотивирующих фраз, звуковые и системные уведомления.
9. Автоматическое дробление создаёт части одной задачи в расписании, а не самостоятельные подзадачи.
10. Экспорт первой версии — резервная копия JSON. Текст для мессенджеров и календарный ICS не входят в объём разработки.

### 2.1. Особенность локального запуска

Для адресов `file:` поведение `localStorage` зависит от браузера и не гарантируется стандартом. Поэтому при старте обязательна проверка чтения и записи. При доступном хранилище приложение работает штатно; при недоступном сохраняет работоспособность в памяти и явно сообщает, что изменения нужно экспортировать до закрытия. Не заменять локальный запуск обязательным сервером. Это ограничение платформы описано в [документации localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

## 3. Пользователь и доступные действия

Роль одна — владелец личного планировщика в текущем браузере. Вход и разграничение прав отсутствуют.

| Область | Что может сделать пользователь |
| --- | --- |
| Сегодня | Задать начало и окончание дня; добавить, изменить, удалить, выполнить задачу; менять порядок и тип; отложить задачу. |
| Расписание | Смотреть интервалы и свободное время; видеть части задачи; отмечать выполненную часть; изменять отдельные перерывы; видеть конфликты. |
| Фиксированные блоки | Использовать начальные блоки «Завтрак», «Обед», «Сборы Ромы в школу»; добавлять свои; менять название, время, длительность и вид «Отдых / Занятое время»; включать и отключать их. |
| Не сегодня | Хранить отложенные задачи; добавлять и редактировать их; менять тип и порядок; переносить на сегодня; выполнять и удалять. |
| Незавершённые | Смотреть невыполненные задачи других дат; искать их; переносить на сегодня или в «Не сегодня»; выполнять или удалять. |
| Архив | Искать выполненные задачи; фильтровать по дате; видеть самые свежие первыми; восстанавливать задачу на прежнее место; удалять запись. |
| Данные | Скачать резервную копию; проверить и импортировать копию с заменой текущих данных; видеть оценку объёма хранения; вручную очистить старый архив после подтверждения и сохранения копии. |

## 4. Словарь и общие правила

- **Сегодня** — локальная календарная дата устройства. В интерфейсе нет выбора будущего дня.
- **День** — один календарный день с началом и окончанием в пределах этой даты. Ночные интервалы через полночь не поддерживаются.
- **Главная / Мелкая** — тип задачи. Все главные выше всех мелких. Внутри раздела выше расположенная задача важнее.
- **Приоритет** — позиция в последовательности «Главные по порядку, затем Мелкие по порядку». Отдельного числового приоритета и сортировки по уровням нет.
- **Обычная задача** — имеет длительность и автоматически получает интервалы.
- **Фиксированная задача** — имеет начало и окончание; её время задаёт пользователь, дробление запрещено.
- **Бытовой блок** — настраиваемый фиксированный резерв времени текущего дня с названием и видом «Отдых» или «Занятое время». Название не определяет поведение расчёта. Это отдельный элемент настроек дня, а не карточка в приоритетном списке.
- **Часть задачи** — рассчитанный непрерывный интервал обычной задачи. Все части имеют один идентификатор исходной задачи.
- **Оставшаяся длительность** — общая длительность обычной задачи минус минуты подтверждённых выполненных частей.
- **Перерыв** — отдых между рабочими интервалами. По умолчанию 10 минут, отдельное значение можно изменить.
- **Не сегодня** — общий список без даты плана, сохраняемый между днями.
- **Незавершённые** — активные задачи с датой, отличающейся от сегодняшней. Основной случай — задачи прошлых дней. Если часы устройства переведены назад, записи более поздней даты также остаются здесь с подписью своей даты.
- **Архив** — выполненные задачи, отсортированные по моменту завершения по убыванию.

Изменения сохраняются после каждого завершённого действия. Задача всегда находится ровно в одном месте: в плане одной даты, в «Не сегодня» или в архиве.

## 5. Структура интерфейса

### 5.1. Шапка

Название «Мой день», сегодняшняя дата в русском формате, текущее время, мотивирующая фраза. Кнопки: «Добавить задачу», «Архив», «Резервная копия». Не выводить переключатель будущих дат и выпадающий список «По приоритету» из раннего макета.

### 5.2. Настройки дня

Поля «Начало дня», «Конец дня», «Перерыв по умолчанию». В новой дате начало и окончание пустые: пользователь заполняет их вручную. Стандартный перерыв новой даты — 10 минут.

Ниже — список фиксированных бытовых блоков и кнопка «Добавить блок». Начальные значения новой даты:

| Блок | Начальное состояние новой даты | Поля |
| --- | --- | --- |
| Завтрак | Включён; понедельник–пятница 08:00, суббота–воскресенье 11:00; вид «Отдых». | Изменяемая длительность, по умолчанию 30 минут; окончание рассчитывается. |
| Обед | Включён; понедельник–пятница 13:00, суббота–воскресенье 15:00; вид «Отдых». | Изменяемая длительность, по умолчанию 30 минут; окончание рассчитывается. |
| Сборы Ромы в школу | Понедельник–пятница включён, 06:45–07:30; суббота–воскресенье выключен, часы пустые; вид «Занятое время». | Начальные длительность и начало в будни — 45 минут и 06:45; оба поля изменяемы. |

Рабочие дни здесь означают понедельник–пятницу; отдельного календаря праздников нет. Часы являются редактируемыми начальными значениями новой даты. Для перехода с версии 1.1 однократно обновить только нетронутые старые предустановки текущей даты: прежнее название/вид, пустые часы и прежние длительность/включение. Ручные часы, отключённые пользователем завтрак/обед, переименованные, добавленные и удалённые блоки сохраняются. Исторические даты не обновлять при загрузке другого дня.

Для каждого блока есть переключатель включения, редактирование и удаление с подтверждением. Новый блок имеет обязательное название длиной 1–200 символов, вид «Отдых» по умолчанию, начало HH:MM и целую длительность 1–1440 минут. Начало плюс длительность должно оставаться в пределах той же даты; переход через полночь запрещён. Окончание показывается только для чтения. У отключённого блока допускаются пустые время и длительность. Включённый неполный блок вызывает предупреждение и не занимает выдуманное время.

Можно отключить завтрак или обед, если он уже состоялся вне планируемого интервала. Изменение длительности с 30 на 45 или 60 минут допустимо и сразу пересчитывает план. После создания даты расчёт использует сохранённые вид и часы, без проверки названий или персональных идентификаторов. Новая дата получает три начальных блока из таблицы; пользовательские блоки и изменения прошлой даты автоматически не копируются. Предустановки не создают повторяющихся задач.

### 5.3. Левая колонка

Общий блок «Сегодня» с двумя подразделами: «Главные», затем «Мелкие». В заголовке каждого — количество задач. Подсказка: «Главные выше мелких. Внутри раздела выше — важнее».

Ниже — фисташковый блок «Не сегодня», также с подразделами «Главные» и «Мелкие». Ещё ниже — сворачиваемый блок «Незавершённые» с поиском по названию и фильтром по дате.

### 5.4. Правая колонка

«План дня»: сводка времени, список предупреждений, вертикальная временная лента от начала до окончания дня. Лента содержит интервалы задач, части задач, фиксированные дела, бытовые блоки, перерывы и свободные промежутки.

Под лентой показывать ссылку «Выполнено сегодня: N», открывающую архив с соответствующим фильтром. Завершённые задачи не рисовать как занятые интервалы в пересчитанной ленте: их прежнее будущее время освобождено. Прежние запланированные части сохраняются в данных истории. Не изображать их как измеренное фактическое время работы: таймера работы в продукте нет.

Над лентой есть кнопка «Пересчитать от текущего времени». Она выполняет полный пересчёт обычных невыполненных дел по разделу 9, сохраняя фиксированные часы, бытовые блоки и отдых. Это действие для опоздания или изменения дня; сдвиг всех фиксированных событий на N минут отсутствует.

#### 5.4.1. Сетка, размеры и прокрутка

- Базовый масштаб фиксированный: 2 px на минуту, 120 px на час. Отметки каждые 15 минут; полные часы подписаны и выделены сильнее. Дополнительно подписать точные начало и окончание дня, если они не кратны 15 минутам.
- Положение интервала: `(начало − начало дня) × 2 px`; его высота: `длительность × 2 px`. Не растягивать короткие дела ради текста, иначе шкала потеряет смысл.
- Область ленты имеет вертикальную прокрутку, высоту `min(70vh, 720px)` с минимумом 320 px. Шапка шкалы и сводка находятся вне прокрутки. При первом открытии показать область текущего времени; до начала дня — начало, после окончания — конец. Пересчёт сохраняет положение прокрутки, пока пользователь сам не нажмёт «К текущему времени».
- Интервал высотой менее 44 px показывать компактной полосой без обрезанного текста. Выбор мышью, касанием или клавиатурой открывает под видимой областью ленты панель с полным названием, часами, длительностью и доступными действиями, включая «Часть выполнена». Для каждой полосы обязательно доступное имя.
- Для группы пересекающихся фиксированных блоков использовать параллельные колонки. Интервалы отсортировать как в разделе 9.3; каждому назначить первую колонку, последний интервал которой уже закончился. Ширина колонок одинакова внутри связной группы пересечений. Красная рамка и значок конфликта сопровождаются текстом в панели и списке предупреждений. Блоки не перекрывают друг друга непрозрачными карточками.
- Бытовые блоки отдыха и короткие перерывы отличаются подписью и мягкой заливкой, свободное время — незаполненной областью. Линия «Сейчас» обновляется без перемещения остальных интервалов. За границами дня линия скрыта.

### 5.5. Карточка задачи

Название, тип, длительность/остаток, фиксированное время при его наличии, ручка перетаскивания, кнопка выполнения, кнопка «Не сегодня» или «На сегодня», меню дополнительных действий. Если задача выполнена частично, показывать «Осталось 40 из 60 мин».

Самая важная активная задача сегодняшнего списка получает рамку, акцент и подпись «Самый высокий приоритет». Если главных нет — выделяется первая мелкая. Даже не помещающаяся или конфликтующая задача сохраняет приоритет. В «Не сегодня», незавершённых и архиве такая подпись не отображается.

### 5.6. Диалоги

Использовать собственные доступные диалоги для добавления/редактирования, удаления и импорта. Enter сохраняет валидную форму, Escape отменяет. При закрытии несохранённой изменённой формы запросить подтверждение потери черновика. Фокус удерживается внутри открытого диалога и возвращается к вызвавшему элементу.

### 5.7. Прогресс сегодняшних задач

В блоке «Сегодня» над разделами задач показывать «Выполнено X из Y», полоску и процент `round(X / Y × 100)`. X — сохранённые архивные задачи из плана текущей даты, завершённые в эту локальную дату; Y — X плюс количество активных задач сегодняшнего плана. Главные, мелкие и фиксированные задачи имеют одинаковый вес. Задачи «Не сегодня», других дат и бытовые блоки не учитываются. Подтверждение части не увеличивает X до завершения всей задачи.

При Y = 0 показать «Задач на сегодня пока нет», пустую полоску и 0%. Завершение, отмена, восстановление, перенос, добавление и удаление сразу обновляют показатель. Удалённые архивные задачи исключаются; возврат из архива уменьшает X и возвращает задачу в активную часть Y. Прогресс вычисляется из текущих задач, отдельно в хранилище не сохраняется. Для полоски дать доступное имя и текстовую подпись X/Y.

## 6. Создание и редактирование задач

### 6.1. Поля формы

| Поле | Правило |
| --- | --- |
| Название | Обязательная строка после удаления пробелов по краям; от 1 до 200 символов. |
| Тип | «Главная» или «Мелкая»; по умолчанию «Главная». |
| Куда добавить | «Сегодня» или «Не сегодня»; по умолчанию «Сегодня». Будущую дату выбирать нельзя. |
| Режим времени | «По длительности» или «Фиксированное время»; по умолчанию первый. |
| Длительность | Для обычной задачи целое число 1–1440 минут. Поле обязательно; значение по умолчанию не подставляется. |
| Начало/окончание | Для фиксированной задачи обязательны оба значения в формате HH:MM; окончание строго позже начала. |

Описание, заметки, ссылки и повторение отсутствуют. Одинаковые названия разрешены: это разные задачи с разными идентификаторами.

Новая задача добавляется в конец выбранного подраздела. Выбор типа меняет подраздел. Для редактирования тип и место можно изменить той же формой; при смене подраздела задача попадает в его конец, если конкретное место не задано перетаскиванием.

Фиксированной задаче в «Не сегодня» также нужны сохранённые начало и окончание; конфликты сегодняшнего плана для неё не проверяются, пока она не возвращена на сегодня.

Синтаксические ошибки блокируют сохранение формы. Конфликты расписания, перегрузка и недостаток отдыха не блокируют сохранение валидной задачи — они показываются в плане и остаются видимыми до исправления.

### 6.2. Выполненные части

У части обычной задачи в расписании есть кнопка «Часть выполнена». Действие учитывает ровно её показанную длительность и время нажатия. Части уже подтверждённого выполнения повторно не генерируются. Пока остаток больше нуля, карточка остаётся активной. Когда остаток равен нулю, задача автоматически архивируется.

Кнопка выполнения на основной карточке означает «вся оставшаяся задача выполнена» и сразу архивирует её. Фиксированные задачи выполняются только целиком. При редактировании частично выполненной задачи общая длительность должна быть строго больше уже выполненных минут; для окончательного завершения используется кнопка выполнения.

Смена режима обычной задачи на фиксированный и обратно доступна только до появления выполненных частей. Для частично выполненной задачи соответствующие переключатели заблокированы с объяснением «Сначала завершите или отмените выполненные части».

Последнее выполнение части можно отменить через сообщение «Отменить»; это восстанавливает предыдущий остаток. История отмены всей сессии и отдельный редактор фактического времени не требуются.

## 7. Перемещение и приоритет

1. Перетаскивание карточки внутри подраздела изменяет порядок.
2. Перетаскивание из «Главные» в «Мелкие» и обратно меняет тип и вставляет карточку в выбранную позицию.
3. Перетаскивание между «Сегодня» и «Не сегодня» меняет место и сохраняет идентификатор, название, режим, длительность, выполненные части и настройки перерывов.
4. У области назначения есть подсветка и видимая позиция вставки. Пустые подразделы остаются доступными для сброса карточки.
5. Перетаскивание разрешено только за ручку, чтобы щелчок по выполнению не начинал перенос.
6. Доступные альтернативы: «Выше», «Ниже», «В главные», «В мелкие», «Не сегодня», «На сегодня».
7. Кнопка «На сегодня» вставляет карточку в конец подраздела её типа. Кнопка «Не сегодня» — в конец соответствующего подраздела отложенных задач.
8. Возврат фиксированной задачи сразу использует сохранённые начало и окончание. Не открывать обязательное подтверждение времени. При конфликте, истёкшем интервале или выходе за границы дня показать предупреждение.
9. Изменение приоритета фиксированной задачи не меняет её часы. Приоритет определяет подсветку и предпочтение обычных дел; обязательные фиксированные интервалы являются ограничениями расписания.
10. Архив и незавершённые не являются зонами сброса сегодняшних карточек. Перенос из незавершённых выполняется явными кнопками, чтобы сохранялась понятная связь с исходной датой.

### 7.1. Мышь, касание и стилус

Использовать общий обработчик `pointerdown / pointermove / pointerup / pointercancel` с захватом указателя на ручке. Перенос начинается после движения не менее 6 px; простое касание не переносит задачу. На ручке задать `touch-action: none`, а на остальных областях сохранить обычную прокрутку. Отмена указателя или Escape возвращает исходное место без записи; успешный сброс сохраняется один раз. У края прокручиваемого списка поддержать плавную автопрокрутку. Не полагаться только на нативный HTML5 Drag-and-Drop и не добавлять внешний полифил. Общая модель ввода описана в [документации Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events). Кнопки перемещения остаются доступной альтернативой.

## 8. Фиксированные интервалы и отдых

Фиксированные пользовательские задачи и бытовые блоки с `kind: work` — рабочие интервалы. Блоки с `kind: rest` — интервалы отдыха. Все включённые бытовые блоки резервируют время и сохраняют часы при любом пересчёте. Названия «Завтрак», «Обед» и «Сборы Ромы в школу» — начальные подписи, а не условия в алгоритме.

Бытовой блок вида «Отдых» сам обеспечивает отдых. Между рабочей частью и непосредственно следующим таким блоком, а также сразу после него, дополнительный короткий перерыв не требуется. Свободный промежуток между работой и отдыхом остаётся свободным временем.

Между двумя рабочими интервалами требуется короткий перерыв. Если свободный промежуток уже достаточен, внутри него выделить требуемую длительность как «Перерыв», оставшуюся часть — как «Свободное время». Не считать одни и те же минуты дважды.

Перед первым рабочим интервалом и после последнего автоматический короткий перерыв не требуется. Исключение: после фактического подтверждения выполненной работы резервируется отдых от момента нажатия, если далее остаются рабочие задачи.

### 8.1. Настройка коротких перерывов

- Стандартное значение дня: целое число 0–180 минут; по умолчанию 10.
- Конкретный перерыв можно изменить в таком же диапазоне. Пустое значение не сохраняется.
- Значение 0 допускается, но показывает предупреждение «Между задачами не предусмотрен отдых», если после него следует работа.
- Конкретное значение переопределяет стандартное; изменение стандарта не отменяет индивидуальные значения.
- Переопределение привязано к источнику перерыва: идентификатор задачи и номер её части; для фиксированной задачи номер части 1. Для любого рабочего бытового блока — его идентификатор и номер 1.
- Формат ключа: `task:<id>:part:<n>` или `block:<id>:part:1`. Номер рассчитанной части начинается с 1, в хронологическом порядке среди ещё невыполненных частей текущего расчёта.
- После нового дробления ключ применяется к части с тем же номером. Переопределения временно отсутствующих частей сохраняются, пока существует задача. При выполнении части значение отдыха записывается в событие выполнения независимо от будущих номеров частей.
- Перерыв, не помещающийся между закреплёнными рабочими интервалами, показывается как требование с предупреждением; фиксированные часы автоматически не сдвигаются.

## 9. Время, пересчёт и дробление

### 9.1. Базовые правила времени

Вычисления выполняются целыми минутами. Время ввода преобразуется в число минут от полуночи. Интервалы полуоткрытые: `[начало, окончание)`. Соседние интервалы с одинаковой границей не пересекаются, но между рабочими делами отдельно проверяется отдых.

Использовать локальную дату и часы устройства. Не получать дату через обрезание UTC-строки `toISOString()`. Для текущего времени учитывать секунды: начало нового планируемого дела округляется вверх до ближайшей полной минуты. Например, 11:20:35 означает начало не ранее 11:21.

Исходная граница расчёта: максимум из начала дня и округлённого текущего времени. Если последнее неотменённое выполнение работы требует ещё не истёкшего перерыва, соответствующий остаток перерыва также занимает начало доступного времени. Повторное обновление страницы не запускает этот отдых заново.

Если текущее время раньше начала дня, расчёт начинается с начала дня. Если не раньше окончания — новых интервалов работы нет, оставшиеся задачи получают предупреждение о завершении дня.

### 9.2. События пересчёта

Пересчитывать расписание после сохранения формы, изменения границ, времени бытовых блоков, порядка, типа, места задачи, перерыва, выполнения части/задачи, отмены, восстановления, удаления и импорта.

Текущее время и дату обновлять каждые 30 секунд и при возвращении вкладки на передний план. Обычное обновление часов не передвигает уже показанное расписание каждую минуту: оно только обновляет указатель времени и подписи прошедших интервалов. Полный пересчёт происходит при перечисленных действиях и при открытии/возобновлении страницы. Никогда автоматически не считать интервал выполненным по часам.

### 9.3. Фиксированные интервалы

Сначала собрать и отсортировать фиксированные задачи и включённые бытовые блоки по началу, затем по окончанию, затем по постоянному идентификатору.

Если фиксированная задача полностью раньше текущего времени и ещё не выполнена, оставить её в списке с предупреждением «Фиксированное время прошло». Её не переносить автоматически и не резервировать повторно в будущем. Если интервал уже начался и ещё продолжается, его оставшаяся часть остаётся занятой до исходного окончания.

Прошедший бытовой блок показывается в истории ленты без предупреждения о невыполнении: у него нет отметки выполнения. Пересечение и выход за границы проверяются у всех фиксированных интервалов исходного плана, включая прошедшие.

При пересечении фиксированных интервалов показывать оба исходных блока и конфликт. Для размещения обычных задач занятое время считать объединением пересекающихся интервалов; ни в одну занятую минуту обычную задачу не размещать. Сводку в таком состоянии помечать «Есть конфликты», а не «Всё помещается».

Для вычисления свободных промежутков каждый объединённый занятый интервал считается рабочим, если в него входит хотя бы одна фиксированная задача или бытовой блок с `kind: work`; иначе он считается отдыхом. Это консервативное правило для уже конфликтующего плана. Интервалы за границами дня обрезаются только для размещения и рисования ленты; их исходные часы остаются видимыми в карточках и предупреждениях.

### 9.4. Однозначный алгоритм размещения обычных задач

Минимальная промежуточная часть обычной задачи — **15 минут**. Целая короткая задача или последняя часть может быть меньше 15 минут. Это техническое правило первой версии, уменьшающее количество неудобных мелких фрагментов.

Если остаток равен 20 минутам, а вместимость после учёта перерывов равна 15, разместить промежуточную часть на 15 минут. Оставшиеся 5 минут становятся последней частью и могут занять следующий слот вместимостью хотя бы 5 минут. Такой хвост не блокируется правилом 15 минут. Если 5-минутный слот встречается до создания хвоста, исходные 20 минут в него не дробятся; проверить следующую короткую задачу.

1. Создать очередь обычных задач по приоритету: главные, затем мелкие; учесть оставшиеся длительности. Фиксированные задачи из очереди исключить, поскольку они уже резервируют время.
2. Обходить свободные промежутки между занятыми фиксированными интервалами по времени, начиная с границы расчёта.
3. Для кандидата вычислить самое раннее начало: если предшествующий интервал — работа, это окончание той работы плюс требуемый отдых; после бытового блока отдыха или в начале дня дополнительного отдыха нет. Учесть также остаток отдыха после события фактического выполнения.
4. Правый резерв кандидата равен его короткому перерыву, если промежуток заканчивается началом фиксированной работы; иначе равен 0. При отрицательной вместимости кандидат не помещается. Формула вместимости: конец свободного промежутка минус самое раннее начало минус правый резерв.
5. Проверять кандидатов в порядке приоритета. Если весь остаток кандидата не больше вместимости, разместить его целиком. Иначе разместить часть, равную вместимости, если она не меньше 15 минут. При вместимости меньше 15 и большем остатке пропустить кандидата в этом промежутке и проверить следующий.
6. За счёт предыдущего правила менее приоритетная короткая задача может занять место, непригодное для части более важной задачи. Сам порядок карточек при этом не меняется.
7. При успешном размещении зафиксировать необходимый левый перерыв и рабочую часть. Перед новым кандидатом снова вычислять левый перерыв от предыдущей работы. Не резервировать короткий перерыв после уже размещённой части только потому, что в списке ещё есть неразмещённые задачи: он становится реальным интервалом лишь при размещении следующей работы либо перед закреплённой работой на правой границе.
8. После размещения снова начать выбор с самой приоритетной задачи, у которой есть остаток. Если интервалы одной задачи непосредственно соседствуют без фиксированного дела или отдыха между ними, объединить их в одну часть.
9. Если ни один кандидат нельзя разместить, закрыть промежуток. Если справа фиксированная работа, выделить необходимый отдых после последней работы в пределах этого промежутка; при недостатке времени выдать REST_NO_ROOM. Перед бытовым блоком отдыха и окончанием дня остаток остаётся свободным. Алгоритм обязан завершаться: каждый шаг размещает минуты, переходит к следующему кандидату или закрывает промежуток.
10. По окончании дня остатки задач сохраняются в карточках с пометкой «Не помещается: N мин». Автоматический перенос на другой день запрещён. Время всех частей каждой задачи плюс неразмещённый остаток строго равно её оставшейся длительности до расчёта.

Если последний рабочий интервал заканчивается у границы дня, после него отдых не резервируется. Даже при наличии неразмещённых задач нельзя сокращать последнее помещающееся дело ради перерыва, после которого никакая работа уже не помещается. Например, при дне на 60 минут и задачах A на 60 минут и B на 30 минут разместить A целиком; B остаётся неразмещённой, после A отдыха нет.

### 9.5. После выполнения и частичного выполнения

Время нажатия является событием завершения; фактическое время начала не измеряется. Сохранить длительность подтверждённой части, её прежний запланированный интервал, момент нажатия и требуемый перерыв после работы.

Пересчитать только невыполненный остаток от текущего времени с учётом этого перерыва. Завершённая задача не продолжает занимать свой прежний будущий интервал. Другие незавершённые фиксированные задачи и бытовые блоки сохраняют часы.

Если выполнена фиксированная задача заранее, её оставшееся зарезервированное время освобождается; отдых начинается от фактического нажатия. В «Не сегодня» и незавершённых можно отметить задачу выполненной, но такое действие не меняет загрузку сегодняшнего дня и не добавляет в него перерыв.

Любой бытовой блок с `kind: rest`, перекрывающий время требуемого отдыха после выполненной работы, засчитывается в этот отдых. Если блок короче ещё не истёкшего отдыха после фактического выполнения, его конец не отменяет оставшийся обязательный отдых. Прошедшие минуты не добавляются заново при последующих пересчётах.

## 10. Сводка и предупреждения

### 10.1. Показатели

В сводке показывать:

| Показатель | Расчёт |
| --- | --- |
| Длительность дня | Окончание минус начало. |
| Доступно от текущего времени | Максимум из 0 и окончания минус максимум начала дня и округлённого текущего времени. |
| Размещённые дела | Минуты будущих обычных частей и оставшихся фиксированных рабочих интервалов. |
| Отдых | Минуты будущих бытовых блоков с `kind: rest` и реально размещённых коротких перерывов. |
| Не размещено | Сумма оставшихся минут обычных задач, для которых не найдено время. |
| Свободно | Будущие доступные минуты, не занятые объединением рабочих интервалов, бытовых блоков и размещённых перерывов. |

Все бытовые блоки с `kind: work` входят в рабочее занятое время. При конфликтующих интервалах считать объединение минут, а подписи сумм помечать предварительными. Пропущенные фиксированные дела показывать отдельным количеством; их прошлые минуты не добавлять к будущей загрузке.

Не называть сумму неразмещённых минут точной величиной, на которую нужно продлить день: при продлении могут понадобиться дополнительные перерывы. Точная подпись — «План перегружен: не размещено N мин задач».

### 10.2. Виды предупреждений

| Код | Когда появляется | Сообщение/действие |
| --- | --- | --- |
| DAY_INCOMPLETE | Не заполнены границы либо окончание не позже начала. | «Укажите корректное начало и окончание дня». Задачи сохраняются, расчёт остановлен. |
| BLOCK_INCOMPLETE | Включён бытовой блок без нужного времени или длительности. | «Укажите время и длительность: …» с фактическим названием блока. Остальная лента предварительная. |
| FIXED_OVERLAP | Два фиксированных интервала пересекаются. | Названия обоих дел и интервал пересечения; кнопки редактирования. |
| OUTSIDE_DAY | Фиксированный интервал выходит за границы дня. | Название и указание, какая граница нарушена. |
| FIXED_MISSED | Время невыполненной фиксированной задачи прошло. | «Время задачи … прошло»; действия «Изменить», «Не сегодня», «Выполнено». |
| REST_MISSING | Между работой задан нулевой отдых. | «Между задачами не предусмотрен отдых»; переход к настройке. |
| REST_NO_ROOM | Отдых между закреплёнными рабочими интервалами не помещается. | «Между … и … не помещается перерыв: нужно N мин, доступно M мин». |
| OVERLOAD | Есть неразмещённый остаток обычных задач. | «План перегружен: не размещено N мин задач». Названия задач и кнопки «Не сегодня». |
| DAY_ENDED | День закончился и остались активные задачи. | «Рабочий день завершён. Остались невыполненные задачи». |
| STORAGE_FAILED | Чтение/запись localStorage недоступны или не удались. | «Изменения сейчас не сохраняются в браузере. Скачайте резервную копию». |
| STORAGE_NEAR_LIMIT | Оценка размера состояния достигла 3 MiB. | «Хранилище почти заполнено»; действия «Скачать копию» и «Очистить старый архив». |
| STORAGE_LIMIT | Оценка превысила защитный предел или запись дала QuotaExceededError. | «Недостаточно места для сохранения. Изменения остаются в памяти»; экспорт и явная очистка. |

Одновременно могут показываться несколько разных предупреждений. Один и тот же конфликт не дублировать. Ошибки сохранения показывать отдельной постоянной полосой над рабочей областью. Порядок предупреждений расписания: ошибки данных, пересечения/границы, пропущенные интервалы, отдых, перегрузка. Предупреждения остаются до исправления; закрытие уведомления не удаляет причину.

Статус «Всё помещается» разрешён только при корректных исходных данных, отсутствии конфликтов и неразмещённых задач, достаточных перерывах и отсутствии пропущенных фиксированных задач. Пустой корректно настроенный день показывает «Добавьте задачи».

## 11. Завершение, архив и восстановление

### 11.1. Завершение

Отметка выполнения убирает карточку из текущего активного списка и помещает её первой в архив. Хранить момент завершения с миллисекундами. При одинаковом времени последняя операция получает больший порядковый номер и показывается выше.

Перед завершением сохранить источник задачи, дату, тип, индекс, идентификаторы соседей и состояние выполненных частей. После завершения показать на 15 секунд сообщение «Задача в архиве» с кнопкой «Отменить». Следующие сообщения не уничтожают возможность восстановления: задача всё равно первая в архиве.

### 11.2. Поиск и сортировка

В шапке постоянно показывать кнопку «Отменить выполнение». Она отменяет последнее сохранившееся выполнение задачи или её последней части, включая после исчезновения уведомления и обновления страницы. Источник — сохранённый `progress`, сортировка по completedAt, затем по номеру события. Повторные нажатия последовательно отменяют предыдущие выполнения; если таких записей нет, кнопка выключена. При полном завершении использовать обычное восстановление на прежнее место, при частичном — отменить только последнюю подтверждённую часть и связанное событие отдыха. В меню активной частичной задачи добавить «Отменить последнюю часть», в архиве действие возврата назвать «Отменить выполнение». Отмена не зависит от 15-секундного уведомления.

Архив открывается на той же странице отдельным крупным диалогом. По умолчанию все даты, сортировка всегда по завершению от новых к старым. Поля: поиск по названию и необязательная дата исходного плана. Дополнительный фильтр «Выполнено сегодня» проверяет локальную дату момента завершения.

Поиск — подстрока без учёта регистра, с удалением пробелов по краям и одинаковой обработкой «е»/«ё». Фильтры применяются совместно. При пустом результате — «Задачи не найдены» и кнопка сброса фильтров.

В записи показывать название, тип, полную длительность, исходное место/дату и дату-время завершения. Для исходного «Не сегодня» вместо даты плана — соответствующая подпись.

### 11.3. Восстановление на прежнее место

Кнопки «Вернуть» и «Отменить» используют одинаковое действие:

1. Отменить только терминальное действие завершения, вернув прогресс, который был перед ним. Ранее действительно выполненные части сохраняются. Связанное событие завершения пометить `cancelled: true`: его искусственно начавшийся отдых тоже отменяется. Остальные события работы и отдыха остаются в силе.
2. Вернуть исходный тип и источник. Сегодняшняя задача возвращается в сегодняшний план; старая — в план исходной даты и блок «Незавершённые»; отложенная — в «Не сегодня». Не предлагать выбор другой даты в этом действии.
3. Если сохранился прежний следующий сосед в том же подразделе — вставить перед ним. Иначе, если сохранился предыдущий — после него. Иначе использовать прежний индекс, ограниченный текущей длиной подраздела.
4. Пересчитать сегодня, если изменён сегодняшний план; показать все новые конфликты. Исходные фиксированные часы сохраняются.
5. Если возвращена старая задача, показать «Возвращено в незавершённые за …» и кнопку перехода к ней. Для её переноса на сегодня использовать отдельную кнопку «На сегодня».

Восстановление не дублирует задачу: идентификатор остаётся прежним, архивная запись этой задачи исчезает. При повторном завершении появляется новая дата завершения, и запись снова оказывается сверху.

## 12. Незавершённые задачи, смена даты и удаление

### 12.1. Незавершённые

Блок по умолчанию свёрнут; заголовок показывает количество. Задачи сгруппированы по исходной дате от новой к старой, внутри — главные и мелкие по сохранённому порядку. Поиск по названию работает как в архиве; фильтр выбирает дату из существующих записей.

Действия: «На сегодня», «Не сегодня», «Выполнено», «Удалить». Старое расписание и границы дня здесь не редактируются. Можно открыть карточку для просмотра; редактирование названия/длительности доступно после переноса в активный раздел.

Перенос на сегодня меняет дату на текущую, сохраняет тип и оставшийся объём работы, вставляет задачу в конец подраздела. Для фиксированной задачи сразу используются сохранённые часы и показываются возможные конфликты. Перенос в «Не сегодня» удаляет назначение даты, сохраняя режим и часы.

### 12.2. Смена даты

Проверять дату при загрузке, каждые 30 секунд и при возвращении вкладки. В новую дату открыть новый сегодняшний план с пустыми границами, стандартным перерывом 10 минут и начальными состояниями бытовых блоков из раздела 5.2.

Все активные задачи прежней даты остаются на ней и становятся видимыми в «Незавершённых». Ничего автоматически не переносить в сегодня, «Не сегодня» или архив. Отложенные задачи и архив общие и сохраняются. Фраза меняется на новую.

Если в 23:59 пользователь выполнял задачу без отметки завершения, в 00:00 она остаётся активной на прежней дате с тем же остатком. Прошедшая запланированная часть не считается выполненной автоматически. Показать сообщение «Начался новый день. Незавершённая задача осталась за …» с переходом к прежней карточке. Пользователь может отметить её выполненной в «Незавершённых» или явно перенести на сегодня; новый день не получает задачу и её время без этого действия. Все уже подтверждённые до полуночи части сохраняются.

Приложение не отслеживает фактическое начало работы, поэтому сообщение о сохранённых незавершённых показывать при наличии любых активных задач прежней даты. Если была открыта конкретная карточка, ссылка ведёт к ней; иначе — к списку соответствующей даты с количеством задач. Не определять выполнение по последнему плановому интервалу.

Перетаскивание при смене даты отменяется без изменения исходной задачи. Открытая панель вчерашней части закрывается с сообщением, что её выполнение нужно подтвердить через «Незавершённые». При обработке нажатия ещё раз проверить текущую дату; устаревшая кнопка части не должна списывать минуты из нового плана. Это не ночной режим работы: пересекающиеся с полуночью интервалы по-прежнему не создаются.

Если при смене даты открыт черновик формы для вчерашнего «Сегодня», сохранять его в памяти и показать выбор «Добавить на сегодня» / «Добавить в Не сегодня» / «Отменить». Не записывать черновик незаметно на старую дату.

### 12.3. Удаление

Удалять задачу только после подтверждения «Удалить задачу “…”?». Отмена ничего не меняет. Удаление из архива удаляет саму задачу, а не только её видимость в архиве. В обычных списках массового удаления нет; отдельная управляемая очистка старого архива описана в разделе 14.6. Штатной кнопки очистки всего хранилища нет.

После удаления убрать задачу из всех индексов и связанных переопределений перерывов; пересчитать сегодня при необходимости. Исторические события завершённой работы текущего дня можно сохранить без ссылки на удалённую карточку, чтобы не отменять уже начавшийся отдых. Их поле `taskId` становится `null`.

## 13. Мотивирующая фраза

В `script.js` встроить набор из 31 уникальной короткой поддерживающей фразы на русском языке. Полный набор является содержимым приложения и не дублируется в ТЗ. При реализации подготовить все 31 фразу: одно предложение, 20–120 символов, без давления, обещаний результата и вымышленных авторских атрибуций. Примеры тона: «Маленькие шаги тоже ведут к большим результатам»; «Сегодня можно двигаться в своём темпе». Редактор фраз отсутствует.

Фраза определяется календарным днём, а не случайным выбором при загрузке. Номер дня: `floor(Date.UTC(локальный год, локальный месяц − 1, локальное число) / 86400000)`; индекс — положительный остаток деления на 31. Формула использует локальные календарные компоненты, сохраняя одинаковую фразу в пределах дня при разных часах и переходах времени. Соседние даты получают разные фразы, после 31 дня набор повторяется. При смене локальной даты обновить фразу автоматически.

## 14. Данные и localStorage

### 14.1. Основной объект

Использовать один основной ключ `moy-den.state.v1` и отдельный служебный ключ для проверки доступности `moy-den.storage-test`. Проверочный ключ удалить после проверки. Запрещено использовать `localStorage.clear()`.

| Поле корневого объекта | Тип / назначение |
| --- | --- |
| schemaVersion | Целое 1. |
| revision | Неотрицательное целое; увеличивается на 1 после каждой успешной записи. |
| nextSequence | Неотрицательное целое для разрешения одинаковых времён завершения. |
| updatedAt | ISO-дата-время UTC последней сохранённой операции. |
| tasks | Объект с ключами — постоянными строковыми идентификаторами задач. |
| days | Объект с ключами — локальными датами YYYY-MM-DD. |
| backlog | Объект с массивами `mainIds` и `smallIds`. |
| ui | Состояние раскрытия «Незавершённых»; поисковые строки и открытые диалоги не сохраняются. |

Идентификаторы должны быть уникальными внутри состояния и сохраняться при перемещениях. Допустим генератор на основе времени, счётчика и случайной части с проверкой отсутствия коллизии; нельзя требовать доступность внешней библиотеки или конкретного API генерации UUID.

### 14.2. Задача

| Поле | Тип / правило |
| --- | --- |
| id | Постоянная непустая строка. |
| title | Валидное название. |
| category | `main` или `small`. |
| mode | `flexible` или `fixed`. |
| durationMinutes | Целое 1–1440; у fixed равно окончанию минус началу. |
| fixedStart / fixedEnd | Целые минуты 0–1439; у flexible оба `null`. |
| status | `active` или `archived`. |
| location | `day`, `backlog` или `archive`. |
| planDate | Валидная календарная дата для `day`; у backlog `null`; для archive хранить дату источника либо `null`. |
| createdAt / updatedAt | ISO UTC. |
| progress | Массив записей выполненных частей: eventId, minutes, completedAt, plannedStart, plannedEnd. Необязательный plannedIntervals — массив снимков `{start, end}` для целого завершения задачи с несколькими рассчитанными частями. Старые записи без этого поля допустимы. |
| archivedAt / archiveSequence | ISO UTC / целый номер для archived; иначе `null`. |
| returnState | Для archived: источник, дата, category, index, previousId, nextId, снимок progress перед терминальным завершением, terminalEventId. Для active `null`. |
| breakOverrides | Объект: номер части как строка → целое число 0–180. |

В основной карточке архивирования терминальное событие учитывает весь невыполненный остаток. При автоматическом архивировании последней части снимок `returnState.progress` фиксируется **до** последнего нажатия, чтобы восстановление отменяло только это действие. В архиве сумма progress равна полной длительности; у активной задачи меньше неё. `terminalEventId` идентифицирует добавленную запись progress и, только при выполнении из плана дня, одноимённое событие в `completionEvents`. Выполнение из «Не сегодня» или «Незавершённых» записывает progress, но не создаёт событие рабочего дня.

Для выполнения одной части `plannedStart / plannedEnd` — её рассчитанные часы. При целом завершении с несколькими размещёнными частями оба поля равны null, а их часы сохраняются в `plannedIntervals`. Неразмещённые минуты тоже подтверждаются целой кнопкой, но не получают выдуманных часов; сумма длительностей снимков не больше `minutes`. Эти поля являются историей до нажатия, а не измерением фактически затраченного времени.

### 14.3. День

| Поле | Тип / правило |
| --- | --- |
| date | Та же YYYY-MM-DD, что в ключе. |
| start / end | Целые минуты либо `null`, если день ещё не настроен. |
| defaultBreakMinutes | Целое 0–180, начальное 10. |
| mainIds / smallIds | Упорядоченные массивы идентификаторов активных задач этой даты и типа. |
| routines | Массив универсальных бытовых блоков; структура ниже. |
| completionEvents | id, taskId или null, at ISO UTC, sequence, confirmedMinutes, breakAfterMinutes, cancelled. Необязательный sourceKey содержит исходный ключ `task:<id>:part:<n>` для истории; старые события без поля допустимы. События только выполнений из плана этой даты. |
| presetVersion | Служебное целое 2 для новых/обновлённых начальных бытовых блоков. Отсутствие поля в старом состоянии допустимо и означает необходимость однократного обновления предустановок, когда эта дата становится текущей. |

Каждый элемент `routines` имеет поля: `id` — постоянная непустая строка, уникальная в состоянии; `title` — 1–200 символов; `enabled` — boolean; `kind` — `work` или `rest`; `start` — целые минуты 0–1439 либо null; `durationMinutes` — целое 1–1440 либо null; `breakOverride` — целое 0–180 либо null. Окончание вычисляется как start + durationMinutes и не хранится отдельно. У включённого неполного блока null означает необходимость заполнения, а не нулевую длительность; готовый интервал должен оставаться в пределах одной даты. Порядок массива — порядок строк в настройках, лента сортирует по часам.

Персональных полей схемы для конкретных названий нет. Начальные три блока из раздела 5.2 — обычные элементы этого массива. Ключ перерыва рабочего блока строится по его id, значение читается из его `breakOverride`. Для rest это значение сохраняется, но не применяется. При смене вида и удалении блока пересчитывается лента; удаление не затрагивает другие блоки.

Результат расчёта ленты, ошибки, доступные минуты и части невыполненных задач вычисляются заново и не являются источником данных. Сохраняются только исходные параметры, подтверждённые части и события выполнения.

Перерыв после фактического выполнения читается из копии `completionEvents.breakAfterMinutes`. Изменение такого уже начавшегося перерыва в ленте меняет именно событие; оно не меняет индивидуальные настройки будущих частей задачи. При отмене выполнения отменяется и это событие отдыха. В конфликтующей объединённой группе рабочих блоков требовать наибольший из их индивидуальных перерывов; при равенстве источник выбирать по более позднему окончанию, затем по идентификатору. Это уточняет консервативное правило раздела 9.3, не сдвигая фиксированные часы.

### 14.4. Инварианты

Каждый активный id находится ровно в одном массиве своего типа и источника. Архивный id не находится в активных массивах. Отдельный массив архива не нужен: он вычисляется по `status` и сортируется по `archivedAt`, затем `archiveSequence` по убыванию. Нет потерянных id, повторений и несовпадений типа/даты.

При переносе частично выполненной задачи её progress сохраняется; сегодняшняя загрузка использует только оставшийся объём. Исторические события выполнения остаются в той дате, где работа была подтверждена. Все события сравниваются по абсолютным ISO-временным меткам; календарное отнесение события фиксируется датой его исходного плана.

### 14.5. Загрузка, запись, сбои

1. Отсутствует основной ключ — создать пустое состояние, без демонстрационных задач пользователя.
2. Ключ существует — разобрать JSON и проверить схему и инварианты. Не заменять повреждённые данные пустым объектом автоматически.
3. При повреждении показать экран восстановления: «Сохранённые данные не удалось прочитать». Доступны скачивание исходной строки в `.txt`, импорт исправной копии и создание пустого состояния только с подтверждением.
4. Изменения применять к копии состояния, проверять инварианты, затем сериализовать, проверять размер по разделу 14.6 и записывать основной ключ внутри try/catch. Показывать «Сохранено» только после успешной записи.
5. При сбое обычной записи сохранить актуальные изменения в памяти, отметить их как несохранённые и оставить экспорт доступным. При последующей успешной записи сохранять всё актуальное состояние.
6. Импорт и явная очистка выполняются иначе: при превышении защитного предела или невозможности записать результат текущие данные не заменять, показать ошибку. Ни одна из этих операций не должна уничтожать текущую рабочую копию при неудаче.
7. При открытии в нескольких вкладках получать изменения через `storage`, если браузер поддерживает общую область хранения. В другой вкладке загружать более новую revision; при открытом черновике сначала показать сообщение об изменении данных и запросить перезагрузку состояния. Не обещать одновременное редактирование: перед записью сравнить revision и при расхождении остановить действие с предложением обновить данные. Механизм события описан в [документации storage](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event).

### 14.6. Объём хранения и управляемая очистка

Лимит JSON-файла при выборе для импорта и фактическая квота браузерного хранилища — разные ограничения. Для localStorage обычно доступно до 5 MiB на origin, при исчерпании возникает QuotaExceededError; другие данные той же области и режим браузера могут уменьшить доступное место. Для `file:` общую квоту нельзя обещать. Основание: [документация квот Web Storage](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Перед каждой записью оценивать собственный размер как `2 × (длина ключа + длина JSON-строки)` байт. Это консервативная оценка строк, а не измеренная свободная квота; окончательная проверка — успешность setItem. `navigator.storage.estimate()` не использовать как доказательство свободного объёма именно localStorage.

- Начиная с оценки 3 MiB показывать постоянное мягкое предупреждение и оценку размера в меню резервных копий.
- Защитный предел записи состояния — 4 MiB по этой оценке. Если новое состояние больше, обычное изменение остаётся в памяти как несохранённое; предыдущую браузерную запись не удалять. Доступны экспорт и очистка. Импорт слишком большого состояния отклоняется до замены данных.
- При QuotaExceededError ниже защитного предела выполнять тот же сценарий несохранённых изменений; не пытаться молча удалить чужие ключи или архив.
- Для превышения квоты показывать STORAGE_LIMIT, для остальных ошибок хранения — STORAGE_FAILED; не дублировать два сообщения об одной неудачной записи.
- 10 000 задач и 3660 дней — ограничения валидации, а не обещание, что такой объём всегда поместится. Реальный приём данных ограничен также размером состояния и результатом записи.
- Автоматическая ротация или удаление архива по возрасту запрещены. Не обрезать progress, returnState и сведения, необходимые для восстановления активных и сохранённых архивных задач.

В меню «Резервная копия» добавить «Очистить старый архив». Диалог выбирает дату «Выполнено раньше …»; по умолчанию 180 дней до сегодняшней даты, максимум — сегодня. Отбираются только архивные задачи, локальная дата завершения которых строго меньше выбранной даты. Сегодняшние завершения и любые активные/отложенные/незавершённые задачи не попадают в очистку.

До удаления показать количество, список названий и оценку освобождаемого объёма; отдельно указать количества удаляемых неиспользуемых записей дней и служебных событий по правилам ниже. Предложить скачать полную текущую копию. Выполнение разрешено только после нажатия «Скачать копию» в этом диалоге и отдельного подтверждения пользователя «Копия сохранена, удалить выбранные записи». Это подтверждение пользователя, а не автоматическая проверка файла на диске. При отмене ничего не менять.

Очистка удаляет выбранные архивные задачи и показанные в предпросмотре неиспользуемые служебные записи. Дополнительно убрать отменённые исторические completionEvents и пустые записи дней старше выбранной даты лишь тогда, когда на них не ссылаются оставшиеся задачи, progress или returnState и они не нужны для текущего перерыва. События сохранённых задач и данные текущего дня не сокращать. Для событий без taskId применять те же условия отсутствия необходимости и исторической даты. Выполнение сначала формирует и проверяет кандидат состояния; только успешная запись заменяет состояние в памяти и браузере. Если результат ещё превышает предел, предложить выбрать больше старых записей, сохраняя текущие данные.

## 15. Резервное копирование и восстановление

### 15.1. Экспорт

Кнопка «Скачать копию» создаёт UTF-8 JSON с полями `product: "moy-den"`, `backupVersion: 1`, `exportedAt` и `state`. Включить все дни, задачи, архив, прогресс, настройки и отложенные дела. Экспортировать текущее состояние памяти, даже если запись в браузер не удалась.

Имя файла: `moy-den-backup-YYYY-MM-DD-HH-mm-ss.json`, по локальному времени скачивания. Использовать Blob и временную ссылку для скачивания; после операции освобождать объектный URL. Не сохранять файл незаметно в произвольную папку.

### 15.2. Импорт

1. Пользователь явно выбирает JSON-файл. Транспортный лимит файла — 8 MiB, не более 10 000 задач и 3660 записей дней. Это защита чтения/парсинга, а не разрешение записать столько в localStorage.
2. Проверить JSON, product, версии, типы, диапазоны, корректность календарных дат и ISO-времён, уникальность id, все ссылки и инварианты, включая универсальные routines. Затем сериализовать кандидат состояния и проверить защитный предел 4 MiB из раздела 14.6. Не исполнять содержимое и не вставлять импортированные строки как HTML.
3. Допускать даты из другого часового пояса или после изменения часов устройства: данные сохраняются со своими датами, а активные записи других дат попадают в «Незавершённые». Это не добавляет возможность планировать будущие дни.
4. При ошибке показать точную причину и путь поля, например `state.tasks.<id>.durationMinutes`. Текущие данные полностью сохраняются.
5. При успешной проверке показать количества активных, отложенных и архивных задач и предупреждение «Импорт заменит все текущие данные». Кнопки: «Скачать текущую копию», «Отмена», «Заменить данные».
6. Импорт заменяет состояние целиком, не объединяет данные. Сохранить новую revision больше текущей. После успешной записи пересчитать сегодня, сбросить поисковые фильтры, закрыть диалоги и показать результат.
7. При отмене или ошибке записи никаких данных не заменять. Не импортировать частично валидный файл.

## 18. Проверочные примеры расчёта

В примерах «сейчас» задаётся явно как тестовое время с нулевыми секундами. Если не указано иное, завтрак/обед/сборы выключены, короткий отдых 10 минут, порядок задач соответствует перечислению. Проверки времени выполняются отдельно от визуальных проверок.

### AT-01. Обычный порядок и отдых

День 09:00–12:00, сейчас 08:00. A — 60 мин, B — 30 мин. Результат: A 09:00–10:00, отдых 10:00–10:10, B 10:10–10:40, свободно 10:40–12:00. После B лишний перерыв не добавляется.

### AT-02. Главные выше мелких

Главная A — 30 мин, главная B — 20 мин, мелкая C — 10 мин. Подсветка у A. После переноса B на первое место расписание начинается с B, подсветка у B. После переноса C в начало главных она становится первой и меняет тип.

### AT-03. Дробление вокруг встречи

День 09:00–12:00, сейчас 08:00. A — 60 мин. Фиксированная встреча 09:40–10:10. Результат: A, часть 1, 09:00–09:30; отдых 09:30–09:40; встреча; отдых 10:10–10:20; A, часть 2, 10:20–10:50. Общая длительность частей A — ровно 60.

### AT-04. Короткое менее приоритетное дело

День 09:00–11:00, сейчас 08:00. A — 60 мин, B — 10 мин, встреча 09:20–09:40. A не получает промежуточную часть 10 минут, поскольку минимум 15. Результат: B 09:00–09:10, отдых 09:10–09:20, встреча, отдых 09:40–09:50, A 09:50–10:50. Карточка A остаётся выше B.

### AT-05. Обед покрывает отдых

День 09:00–12:00, сейчас 08:00. A — 60 мин, B — 30 мин, обед 10:00–10:30. Результат: A 09:00–10:00, обед 10:00–10:30, B 10:30–11:00. Короткие перерывы непосредственно около обеда не добавляются.

### AT-06. Пересечение и сохранение

Две фиксированные задачи 10:00–11:00 и 10:30–11:30. Обе сохраняются, показывается пересечение 10:30–11:00; обычные задачи не занимают 10:00–11:30. Зелёный статус запрещён.

### AT-07. Перерыв между закреплёнными делами

Фиксированные A 09:00–09:30 и B 09:35–10:00. При стандартном отдыхе 10 минут: предупреждение «нужно 10 мин, доступно 5 мин», часы A и B остаются прежними.

### AT-08. Нулевой отдых

A — 30 мин, B — 30 мин; отдых после A установлен 0. Значение сохраняется, интервалы соседствуют, предупреждение об отсутствии отдыха остаётся до исправления.

### AT-09. Завершение раньше запланированного

Сейчас при нажатии 09:20. A была запланирована 09:00–10:00, следующая обычная B — 30 мин. Пользователь завершает A целиком. A первая в архиве; её будущее время освобождено; отдых 09:20–09:30; B начинается 09:30, если нет фиксированных препятствий.

### AT-10. Выполнение части

В AT-03 первая часть A завершена в 09:30. Остаток A — 30 мин, карточка активна, встречи и отдых сохраняются. После завершения последней части задача архивируется. Восстановление после последней части возвращает остаток 30 мин, а не полные 60.

### AT-11. Перегрузка

День 09:00–10:00, сейчас 08:00. A — 50 мин, B — 30 мин. Размещается A 09:00–09:50. Чтобы поставить B, необходим отдых, поэтому её остаток 30 мин не размещён. Сводка «Не размещено: 30 мин», предупреждение о перегрузке; обе карточки сохраняются. Не выводить точное утверждение «продлите день на 30 минут».

### AT-12. Позднее открытие

День 09:00–18:00, сейчас 14:05:20. Первое новое обычное дело начинается не раньше 14:06. Невыполненная фиксированная встреча 10:00–11:00 получает подпись об истёкшем времени; не переносится на 14:06 автоматически.

### AT-13. Предварительно выполненная фиксированная задача

Встреча 10:00–11:00 отмечена выполненной в 10:20. С 10:20–10:30 отдых; после него её прежнее время до 11:00 доступно обычным делам. Другие фиксированные задачи не двигаются.

### AT-14. Последняя часть короче 15 минут

День 09:00–09:50, сейчас 08:00. A — 20 мин; бытовой блок отдыха 09:15–09:45. Результат: A, часть 1, 09:00–09:15; отдых 09:15–09:45; A, последняя часть, 09:45–09:50. Хвост 5 минут допустим, неразмещённый остаток 0, суммарно A занимает 20 минут. До создания хвоста исходную задачу на 20 минут нельзя поместить промежуточной частью в слот 5 минут.

### AT-15. Настраиваемый отдых вместо проверки названия

День 09:00–12:00, сейчас 08:00. A — 60 мин, B — 30 мин. Блок «Прогулка» с kind rest начинается в 10:00 и длится 45 минут. Результат: A 09:00–10:00, прогулка 10:00–10:45, B 10:45–11:15. Дополнительные перерывы около прогулки отсутствуют. После переименования блока в любое другое название интервалы не меняются.

## 20. Требования к реализации и готовности

Сохранить три физических файла, но разделить `script.js` на логические модули с отдельными интерфейсами: TimeUtils, StateValidator, PlannerEngine, TaskActions, StateStore, BackupIO, PlannerView и AppController. Реализовать их объектами или замыканиями внутри одного обычного скрипта; не создавать несколько JS-файлов, ES-модули или общую мешанину обработчиков. TimeUtils, StateValidator и PlannerEngine не должны обращаться к DOM и localStorage; StateStore не должен рассчитывать расписание; PlannerView только отображает результат и передаёт действия контроллеру. Постоянные наборы начальных бытовых блоков и фраз хранить отдельно от функций алгоритма.

Расчёт расписания должен принимать состояние и явное «сейчас», возвращая интервалы, остатки, показатели и предупреждения без записи в хранилище и изменения исходного состояния. Это позволяет проверять сценарии из раздела 18 при фиксированных часах и не требует нескольких физических скриптов.

При отображении пользовательских и импортированных названий использовать безопасную вставку текста. Не применять HTML-интерпретацию к этим строкам. Ввод и импорт не должны создавать исполняемые элементы.

Готовность означает: созданы три файла приложения; реализованы все сценарии UC-01–UC-28; выполнены расчётные примеры AT-01–AT-15 и проверки QA-01–QA-32; нет необъяснимых ошибок в консоли при штатной работе; локальное сохранение проверено закрытием и повторным открытием в целевых браузерах; резервная копия и управляемая очистка проверены восстановлением.

Для нагрузки проверить 500 задач суммарно и 100 активных задач дня: обычные действия и пересчёт должны завершаться без заметного зависания, целевой предел — 300 мс на типичном настольном компьютере. Архив не должен автоматически удаляться ради ускорения; поиск фильтрует сохранённые данные.

Документы `concept.md` и `tz.md` — материалы проекта. Они не являются дополнительными файлами, необходимыми для запуска приложения. На этапе подготовки этого ТЗ код страницы не создаётся.
